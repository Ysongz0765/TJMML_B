# Q2 Tool Use 独立维度可行性检查

## 检查范围

本检查只读取冻结数据 `frozen/v1.0/` 及其数据说明，不重新收集数据，不运行 Q1，不读取 Q1 当前计算输出。检查目标是判断现有数据能否支持在 Q2 中新增独立的 Tool Use / Agent Ability 维度 C6。

## 发现的相关指标

冻结原始数据中可识别到以下工具或 Agent 协议指标：

| 指标/协议 | 最终建模选中模型数 | 协议特征 |
|---|---:|---|
| FrontierSWE（Agent harness） | 6 | 软件工程 Agent 任务，采用同一组来源/报告口径 |
| ProgramBench（Agent harness） | 6 | 代码/程序 Agent 任务，与上述 6 个模型重合 |
| SWE-bench Verified（Agent/tools） | 2 | 仅覆盖两个 DeepSeek 变体，来源与前一组不同 |

冻结建模矩阵共包含 10 个模型。工具/Agent 类最终指标合计涉及 8 个模型，但不是同一个可比 Benchmark 覆盖 8 个模型，而是 6 模型与 2 模型的协议分组；两个分组之间不存在统一量尺下的直接横向可比性。另有 DeepSWE、Terminal-Bench、Toolathlon、SWE Pro 等原始候选记录，但并未形成覆盖全部模型、统一版本、统一 harness、统一工具权限和统一指标定义的冻结输入。

## 覆盖率与可比性判断

1. **覆盖不完整**：不存在覆盖冻结矩阵全部 10 个模型的统一 Tool Use 指标。
2. **协议异质**：不同记录混合 Agent harness、Agent/tools、不同任务版本与不同指标（Accuracy、Resolved、Dominance score 等）。
3. **来源分组明显**：6 模型组与 2 模型组来自不同报告口径，直接拼接或归一化会引入不可识别的协议效应。
4. **概念已部分进入 C4**：FrontierSWE、ProgramBench、SWE-bench Verified 均以代码与软件工程任务为主体，冻结矩阵已把它们纳入 C4。再次作为 C6 使用会造成重复计权与维度含义重叠。
5. **缺乏纯工具调用指标**：现有冻结最终输入未形成覆盖充分的 function-calling 成功率、通用 ToolBench/BFCL/τ-bench 等独立统一矩阵。

## 结论与建议

**当前不建议新增 C6。** 现有数据不足以构造覆盖充分、协议一致、且与 C4 明确区分的 Tool Use 独立能力维度。Q2 代码开发场景继续由 C4（代码与软件工程）、C1（复杂推理）以及 C2/C3 的辅助作用共同表征。

论文限制说明建议采用：

> 受公开一致性工具调用数据覆盖不足及 Agent 评测协议差异限制，本文未单列工具调用维度，而主要由代码与软件工程能力及复杂推理能力共同表征代码开发需求。

若后续人工决定评估 C6，应先冻结一个跨模型统一的 Benchmark、版本、harness、工具权限、网络权限和计分定义，并审查其与 C4 的增量效度；在此之前不得把现有异质指标直接拼接进 Q2 主模型。
